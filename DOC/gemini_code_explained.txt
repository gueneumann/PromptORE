    bert.to(device)
    bert.eval()

    tokens = torch.stack(complete_fewrel['input_tokens'].tolist(), dim=0)
    attention_mask = torch.stack(
        complete_fewrel['input_attention_mask'].tolist(), dim=0)
    masks = torch.Tensor(complete_fewrel['input_mask'].tolist()).long()
    dataset = TensorDataset(tokens, attention_mask, masks)
    dataloader = DataLoader(dataset, num_workers=1,
                            batch_size=256, shuffle=False)

    with torch.no_grad():
        embeddings = []
        for batch in tqdm(dataloader):
            tokens, attention_mask, mask = batch
            tokens = tokens.to(device)
            attention_mask = attention_mask.to(device)

            out = bert(tokens, attention_mask)[0].detach()

            arange = torch.arange(out.shape[0])
            embedding = out[arange, mask]
            embeddings.append(embedding)
            del out
        embeddings = torch.cat(embeddings, dim=0).detach().to('cpu')
        embeddings_list = list(embeddings)

In essence, this code implements the following strategy:

    Prompt Construction: For each relation instance, it constructs a natural language prompt like
    "Entity1 [MASK] Entity2."
    BERT Encoding: It feeds this prompt into a pre-trained BertModel.
    Masked Token Embedding: It extracts the contextualized embedding specifically from
    the position of the [MASK] token.
    Relation Embedding: This extracted [MASK] token embedding is then used as the
    "relation embedding" for that particular entity pair and relation. The idea is that the [MASK] token, positioned between the entities, learns to represent the semantic relationship between them, conditioned on the surrounding context.

This technique is often used in few-shot learning for relation extraction,
where the learned relation embeddings can then be used for tasks like clustering
or similarity-based classification.

Ok, the final [MASK] token's embedding actually represent the relation ?

Yes, that's the core idea and the main purpose behind using the [MASK]
token in that specific prompt structure: the final [MASK] token's contextualized embedding
is intended to represent the relation between the two entities.

Here's why and how it works:

    Contextualization by BERT: BERT's self-attention mechanism processes the entire input sequence ({e1} [MASK] {e2}.)
    bidirectionally. This means that when BERT computes the embedding for the [MASK] token, it takes into account:
        The head entity (e1)
        The tail entity (e2)
        The words surrounding the [MASK] token (the rest of the template, like "is," "of," ".", etc.)
        Crucially, the inherent relationship implied by the presence of e1 and e2 at their specific positions.

    Analogy to Masked Language Modeling (MLM): In its pre-training, BERT's MLM objective teaches it to
    predict the missing word (the [MASK] token) based on its context.
    When you provide a prompt like "{e1} [MASK] {e2}.", you're effectively asking BERT:
    "What word best describes the relationship between e1 and e2 in this context?"
    Even though you're not using BertForMaskedLM to predict a word, the BertModel's internal representation
    for that [MASK] token is a highly informative vector that captures the semantic "slot" or "gap" where
    the relation should be.

    Semantic Meaning of the Slot: By placing [MASK] between the entities, you're creating a
    semantic "slot" that the model is forced to fill with information about how e1 and e2 are related.
    The embedding of this [MASK] token thus becomes a dense vector representation of that relationship.

    Application in Prompt-based Relation Extraction: This technique is a cornerstone of "prompt-based" or
    "P-tuning" methods for relation extraction. Instead of training a classifier on the [CLS]
    token embedding to classify the entire sentence's relation, you extract the [MASK] embedding.
    This embedding can then be used for various downstream tasks:
        Classification: Feed the [MASK] embedding into a simple linear classifier to predict the relation type.
        Few-Shot Learning: In few-shot scenarios, you might compute these embeddings for
        a few examples of each relation and then use metric learning or nearest-neighbor classification
        to predict relations for new, unseen instances.
        The idea is that relations of the same type will have similar [MASK] embeddings.

In summary: While BertModel doesn't predict a token, its output embedding for the
[MASK] token in this specific prompt structure is a very effective and widely used way to obtain a
contextualized semantic representation of the relation between the two entities.
